# Поиск объектов ЕГРН через Личный кабинет Росреестра

## Контекст
`README.md` задаёт поиск по адресу, переход в первый результат, чтение формы собственности и снимок серого блока сведений. `addresses.txt` содержит один адрес на строку; накопительный Excel хранит четыре столбца, PNG сохраняются в `screenshots/`. Поиск выполняется только после ручного входа пользователя в Личный кабинет; между поисками разных адресов — 5 секунд. Вход, CAPTCHA и OCR не автоматизируются: если CAPTCHA появится, остановить запуск с сохранённым результатом, не переходить в гостевой режим.

## Что показал браузерный MCP
На публичной странице `https://lk.rosreestr.ru/eservices/real-estate-objects-online` видны «Выберите тип поиска» (по умолчанию «Поиск по адресу и кадастровому номеру»), необязательное поле «Вид объекта» и доступное для ввода поле `#query` с подписью «Адрес или кадастровый номер». Гостевой экран показывает «Введите символы с картинки» и кнопку «НАЙТИ» (`#realestateobjects-search`), которая до заполнения отключена.

На публичной странице Росреестр прямо указывает, что авторизованным пользователям Личного кабинета проверочный код не требуется. Повторный осмотр той же страницы браузерным MCP в уже авторизованной сессии подтвердил: виден блок Личного кабинета, поля CAPTCHA нет, поле `#query` и кнопка `#realestateobjects-search` сохранены. Гостевая форма не отправлялась; исходы успешной и неудачной CAPTCHA не входят в выбранный режим.

Живой поиск первого тестового адреса в авторизованной сессии выполнен без CAPTCHA. Кнопка «Найти» активируется после заполнения `#query`. Сайт показал `Найдено результатов: 1`; строка данных имеет `[role="row"].rros-ui-lib-table__row`, отдельный заголовок — класс `rros-ui-lib-table__head-row`. Клик по строке открывает модальное окно «Сведения об объекте» на том же URL. Подтверждён серый прямоугольник `.realestate-object-modal .build-card-wrapper.card` (фон `rgb(248, 248, 248)`); для тестового объекта поле «Форма собственности» имеет значение «Частная». Снимок именно этого элемента вернул PNG размером 800×1274 без записи в каталог проекта.

Второй тестовый адрес (`ул.Абеля д.31 кв.7`) дал два результата; первая строка открыла объект `41:01:0010116:7492` с формой «Частная». Искусственный адрес `Тестовый несуществующий адрес 999999` дал `Найдено результатов: 0` и `По заданным критериям поиска объекты не найдены`. Предыдущий счётчик оставался после заполнения адреса, но удалялся из DOM при отправке; затем появлялся новый `span.realestateobjects-wrapper__results__total-count`. Зафиксирован промежуточный экран `Подождите, идет загрузка списка объектов недвижимости...`, который не является результатом. В кабинете есть видимая ссылка «Мои заявки» (`a[href="/my-applications"]`); в DOM может быть и скрытый дубль.

Репозиторий — Python-проект: `pyproject.toml` требует Python ≥3.13, `.python-version` указывает 3.14, `main.py` пуст, зависимостей нет. На первоначальной загрузке формы был фоновый `401` проверки статуса отмены ключа личного кабинета; адресное поле всё равно загрузилось. Один фоновый HTTP-код не равен блокировке поиска.

## Подход

1. **Вход и выход.** Добавить `playwright` и `openpyxl` в существующий `[project].dependencies` в `pyproject.toml`. Точка входа — `uv run python main.py`; передать в `run` каталог `Path(__file__).resolve().parent`, а возвращённый код — в `SystemExit`. Прочитать `addresses.txt` в `utf-8-sig`, обрезать края каждой строки, пропустить пустые и повторные адреса (сохранить порядок первого появления; сравнивать после обрезки без других преобразований). Не открывать браузер, если все адреса уже успешны либо список пуст. Ошибки чтения/сохранения, несовместимый Excel и сбой сайта — сообщение в stderr с текущим адресом, если поиск уже начался, и код `1`; штатное завершение, в том числе с ненайденными адресами, — `0`; Ctrl+C — `130`. Для рабочего контура нет существующего кода, реализовать его в `main.py`: `open_browser() -> ContextManager[Page]` открывает и закрывает браузер, `run(root: Path, *, open_page: Callable[[], ContextManager[Page]] = open_browser, pause: Callable[[float], None] = time.sleep, timeout_ms: int = 30_000) -> int` выполняет весь сценарий. `run` использует переданный `open_page` только после чтения входа/Excel и определения очереди.

2. **Открыть только официальный браузерный интерфейс.** Запустить Playwright Chromium с GUI (`headless=False`, viewport `1900×930`, обычный непостоянный браузерный контекст). Перейти на `https://lk.rosreestr.ru/eservices/real-estate-objects-online`; исключение навигации или HTTP `>=400` для главного документа — остановка. Перед первым запросом, если видимой `a[href="/my-applications"]` ещё нет или видна `#captcha`, вывести инструкцию войти вручную в открытом браузере, вернуться на страницу сервиса и нажать Enter в терминале. После Enter дождаться готовности до 30 секунд; на поисковой странице должны быть видимы `#query`, `#realestateobjects-search`, хотя бы одна ссылка «Мои заявки» по указанному селектору и не должно быть видимого `#captcha`. Не вводить логин/пароль, не сохранять браузерный профиль, cookies или состояние входа. Не использовать скрытые API, OCR, гостевой режим и автоматические повторные входы.

3. **Поиск адреса и переход в карточку.** Проверить схему HTTPS, хост `lk.rosreestr.ru` и путь `/eservices/real-estate-objects-online`, видимый признак кабинета и отсутствие `#captcha` непосредственно перед отправкой, после выдачи и перед сохранением; смена маршрута, исчезновение признака кабинета или появление CAPTCHA в процессе — остановка. Для формы подтвердить выбранное по умолчанию «Поиск по адресу и кадастровому номеру» и незаполненный «Вид объекта» (видимый текст «Выберите значение из справочника»); при несовпадении не отправлять запрос. Заполнить только `#query`; дождаться активной `#realestateobjects-search`; нажать один раз. Перед нажатием взять `ElementHandle` предыдущего видимого `span.realestateobjects-wrapper__results__total-count`, если есть. Ожидать через `page.wait_for_function` до `timeout_ms` новый видимый экземпляр этого элемента (`old` отсутствует либо новая DOM-нода не идентична `old`); не считать старую выдачу свежей даже при совпадающем тексте и не зависеть от наблюдения промежуточного загрузчика. Читать целое `N` из `^Найдено результатов:\s*(\d+)$`. `N=0` только вместе с видимым точным текстом `По заданным критериям поиска объекты не найдены` — штатная неудача, записать её и продолжать. При `N>0` дождаться первой видимой `[role="row"].rros-ui-lib-table__row` в порядке DOM, прочитать её первую `[role="cell"]` как кадастровый номер и кликнуть по строке; не сортировать результаты, не обходить следующие строки. Пустой номер, необъяснимый интерфейс, противоречивая выдача, тайм-аут ожидания или ошибка UI — остановка, не записывать их как «не найдено».

4. **Извлечь форму и сделать снимок только серого блока.** Дождаться видимого заголовка «Сведения об объекте» и единственной видимой `.realestate-object-modal .build-card-wrapper.card`. Внутри выбирать `li.build-card-wrapper__info__ul__subinfo` по точному тексту дочернего `span.build-card-wrapper__info__ul__subinfo__name`, брать `inner_text().strip()` из соседнего `div.build-card-wrapper__info__ul__subinfo__options`. Сверить «Кадастровый номер» с первой ячейкой строки, взять «Форма собственности» как показано; пустое значение при наличии корректного контейнера сохранять пустым, отсутствие/дубликат строки или несовпадение номера — остановка. Вызвать `card.screenshot(type="png", animations="disabled", scale="css", timeout=30_000)` без снимка всей страницы, заголовка модального окна или учётной записи. После фиксации успеха перед следующим поиском закрыть модальное окно кнопкой `.realestate-object-modal__btn` с доступным именем «Вернуться к результатам поиска» (без учёта регистра) и дождаться скрытия карточки. Если закрытие не удалось, уже записанный успех сохранить и завершиться.

5. **Фиксировать каждый завершённый адрес в `result.xlsx`.** До открытия браузера загрузить или создать книгу, лист `Результаты` с точным порядком заголовков: `Адрес`, `Успешен ли поиск`, `Форма собственности`, `Название файла скриншота`. Сразу сохранить новую книгу с заголовками. В существующей книге использовать лист по имени; неверные заголовки, два ряда с одним адресным ключом, отсутствующий ключ у непустого ряда или флаг результата не типа Boolean — считать ошибкой до первого запроса, не перезаписывать книгу. В индексе `адрес → номер строки` пропускать только строки с Excel Boolean `TRUE`; существующие `FALSE` повторять при новом запуске и обновлять на месте; новый адрес дописывать. Для `FALSE` оставлять последние две ячейки пустыми. Для `TRUE` сначала записать PNG в `screenshots/` под именем `<sha256(адрес в UTF-8)>.png`, в Excel — только имя этого файла; не менять сохранённые успешные строки. Каталог `screenshots/` при записи создать, если отсутствует. PNG и книгу публиковать через временный файл в их собственном каталоге и `os.replace`; удалять свои временные файлы при исключении. Если PNG опубликован, а сохранение книги не удалось, старый Excel остаётся читаемым, повторный запуск перезапишет PNG с тем же именем. Незаписанный адрес не помечать `FALSE` при остановке; сохранённые адреса уже на диске.

6. **Разнести запросы на пять секунд.** Работать последовательно в одной вкладке. После завершения и сохранения каждого обработанного адреса и закрытия его карточки при успехе, перед началом следующего реально выполняемого поиска вызвать `time.sleep(5)`, в том числе после пустой выдачи. Не ждать перед первым поиском, после последнего и для пропущенных адресов. Не запускать новые запросы после блокировки, недоступности страницы, смены сессии или другого нарушения описанных состояний. Фоновый статус HTTP сам по себе не заменяет состояние главного документа и поискового интерфейса: например, наблюдавшийся гостевой `401` проверки статуса ключа не мешал загрузить форму.

## Критические привязки

- `README.md` — контракт четырёх столбцов и первый результат без сортировки.
- `addresses.txt` — первый и второй адреса уже проверены на реальном сайте, отличаются номерами квартир.
- `vision_api.md` — описывает OCR другого сценария; не подключать webhook к этому клиенту.

## Проверка

Из корня проекта выполнить `uv sync` и `uv run playwright install chromium` в среде исполнения с доступом к пакетам. Проверка после правок: `uv run python -m unittest discover -s tests -p 'test_lookup.py'`. Создать один `tests/test_lookup.py` со временным каталогом и Chromium headless через `open_page`; перехватить все маршруты в контексте, `route.fulfill` для документа на том же URL и `route.abort` для остальных запросов. HTML воспроизводит наблюдавшиеся состояния и селекторы, не ходит на реальный сайт. Вызвать реальный `run` с `pause=delays.append` и `timeout_ms=1000` в сценарии тайм-аута; рабочие значения по умолчанию не менять. Проверить:

- Положительный поиск из двух строк открывает первую, берёт её «Частная», сохраняет только серый блок в декодируемый PNG, пишет `TRUE` и имя существующего файла. Между запросами сначала оставить старый счётчик/строку, затем заменить счётчик новой нодой с тем же `N`; второй адрес не должен получить данные первого.
- Пустая выдача с подтверждающим текстом даёт `FALSE` и две пустые ячейки. Между этой попыткой и следующим адресом одна пауза `5`; перед первым и после последнего паузы нет.
- Появление `#captcha` после сохранения первого адреса приводит к коду `1`, без гостевого запроса и без строки для незавершённого адреса; книга читается и содержит прежний результат. Аналогично тайм-аут при отсутствии свежего результата не превращается в `FALSE`.
- Повторный запуск на той же книге не отправляет адрес с `TRUE`, повторно обрабатывает строку с `FALSE` без дубля и дописывает новый адрес. Открытие книги с несовместимыми заголовками выдаёт ошибку до браузера и оставляет её без изменений.

Один ручной сквозной прогон из временной копии проекта с двумя строками из начала `addresses.txt` и третьей строкой `Тестовый несуществующий адрес 999999`: `uv run python main.py`, вручную войти и продолжить в терминале. В ожидаемом текущем состоянии сайта первые два ряда имеют `TRUE`, «Частная» и разные PNG серых карточек; третий имеет `FALSE`, обе ячейки данных пусты. Между завершением адреса и началом следующего обращения выдерживается не менее пяти секунд; при повторном запуске сайт получает только один запрос по третьей строке. Если для этого прогона нет оператора с доступом к кабинету или сайт недоступен, не переходить к гостевой проверке: выполнить автономную проверку и явно указать, что сквозной прогон нового CLI не выполнен.

## Допущения

- Один экземпляр программы пишет `result.xlsx` за раз. Повторный запуск возобновляет файл результатов, но вход в кабинет выполняется заново.
